# Monthly / Quarterly Operating Review

The monthly operating review is the AM team's recurring discipline between
quarterly asset reviews — a faster, denser cadence that catches problems early
and feeds the QAR with already-formatted analysis. This reference covers the
review workflow, the standard exhibits, and how to compose them from the
helper scripts.

If you're producing a one-time IC memo or the formal QAR, use
[`quarterly-asset-review.md`](quarterly-asset-review.md). This file is the
operating-cadence companion.

## What an operating review looks like

A typical monthly package contains four sections, each ~1 page:

1. **Operating snapshot** — physical/economic occupancy, in-place rent,
   leasing activity, NOI for the month and T-12, vs. budget.
2. **Variance analysis** — line-item walk vs. baseline(s). Most institutional
   shops show **at least two baselines** simultaneously — usually budget and
   prior-period (or T-12 average) — so movements are seen both against plan
   and against trend.
3. **Operating exceptions** — flagged lines outside their threshold band. Tax,
   insurance, R&M spikes; sudden occupancy moves; bad-debt creep.
4. **Debt / covenant status** — DSCR / DY / LTV vs. covenants; YM clock if a
   refi is on the horizon.

A quarterly review folds in valuation update and the recommendation cycle on
top.

## The four-axis pivot

Operating dashboards routinely pivot the same data along four axes. Make
sure your output supports the rotation:

| Axis | Values |
|---|---|
| **Period** | This month / QTD / YTD / T-3 (annualized) / T-6 / T-12 |
| **Baseline** | Underwriting / Budget / Prior period / T-12 average |
| **Basis** | `$` total / `$/unit/month` / `%` of EGR / `%` of OpEx / `%` of baseline |
| **Comparison direction** | Favorable-only / unfavorable-only / both |

A line that looks fine on `$ total` (a $20k variance on a $400k tax bill
sounds small) may look bad on `$/unit/mo` ($8/unit/mo is meaningful for a
200-unit deal) or `% var` (5% over). Always check at least two basis views.

Generate with `scripts/variance_report.py`:

```bash
python scripts/variance_report.py --csv lines.csv \
    --baseline "Budget" --basis dollar
```

The `--basis` flag toggles the variance column display between `dollar`,
`per_unit_mo`, `pct_of_egr`, `pct_of_opex`, and `pct_var`. Same data, four
ways to read it — see "the four-axis pivot" above.

### Exhibit C — Operating exceptions

```
OPERATING EXCEPTIONS  (3 flagged)
─────────────────────────────────────────────────────────────────────
[CRITICAL]
  !! Insurance: +40.0% vs Budget ($140k vs $100k) -- $40k unfavorable

[WARN]
   ! Vacancy:      +14.0% vs Budget ($57k vs $50k)   -- $7k unfavorable
   ! Property Tax:  +9.0% vs Budget ($109k vs $100k) -- $9k unfavorable
─────────────────────────────────────────────────────────────────────
```

Auto-generated by `flag_lines()` in `variance_report.py`. Default
thresholds tighter on tax/insurance:

| Line | Warn | Critical |
|---|---:|---:|
| Property Tax | 5% | 15% |
| Insurance | 10% | 15% |
| All other lines | 10% | 20% |

Override per-deal with custom `Threshold` rules. Direction defaults to
unfavorable-only so the report doesn't drown in favorable-side noise; switch
to `direction="favorable"` or `"either"` for a full picture.

CLI:

```bash
python scripts/variance_report.py --csv lines.csv \
    --baseline Budget --basis dollar --flags
```

### Exhibit D — Debt + YM clock

For loans within 24 months of maturity, surface the YM clock in every
monthly package:

```bash
python scripts/yield_maintenance.py \
    --upb 8500000 --loan-rate 0.0425 --treasury-rate 0.0410 \
    --maturity 2026-02-10 --today 2025-08-14 \
    --amort-yrs 30 --open-period-months 3
```

Outputs:
- Current YM penalty ($ and % of UPB)
- Open-period flat fee
- Savings if wait to open period
- Months to open period / months to maturity

This is the input to refi-timing decisions. When the spread is tight (loan
rate ≈ Treasury), YM may be LESS than the 1% open-period fee — wait doesn't
save you anything and the analyst should refi immediately.

## Composing the package

For a single-property monthly review:

1. **Rent roll** snapshot: `rent_roll.py --csv rent_roll.csv --as-of 2026-04-30`
2. **NOI bridge** vs prior-period: `noi_bridge.py --csv noi_lines.csv \
   --baseline-label "Prior T-12" --actual-label "Current T-12"`
3. **Variance report** vs budget with flags: `variance_report.py --csv \
   lines.csv --baseline Budget --basis dollar --flags`
4. **YM clock** if loan within 24 months of maturity: `yield_maintenance.py ...`
5. **Covenant status**: `debt_metrics.py --noi ... --loan-balance ... --rate ...`

The same `lines.csv` can serve both the NOI bridge and the variance report —
the difference is just the script reading either two columns (bridge) or N
columns (variance). The variance report is a strict superset.

## Cross-property roll-up

For portfolios > ~10 properties, build a thin wrapper script that loops over
per-property CSVs and aggregates into a fund-level variance pack. The
underlying helpers (`variance_report.py`, `flag_lines`) operate on Python
data structures, so this is a 50-line composition exercise. Keep the
property-level reports as separate exhibits in the appendix.

## Common pitfalls

- **Single-baseline tunnel vision.** A 5% NOI miss vs. budget can be a 15%
  beat vs. T-12 trend (or vice versa). Show both.
- **Mixing T-3 annualized with T-12.** T-3 catches recent moves but is
  noisy; T-12 smooths but lags. State which you're using in every exhibit.
- **Comparing cash-basis monthly to accrual budgets.** Property tax, insurance,
  and management fees are often booked as 1/12 in accrual budgets but lumpy
  in cash. Normalize the basis or annotate the line.
- **Ignoring favorable variances.** A 20%-favorable variance often means a
  one-time event or a budgeting error — both worth understanding even if
  the impact is positive.
- **Reporting `% of EGR` for expense lines without disclosure.** A line at
  "2% of EGR" sounds modest; on a $5M revenue base that's $100k. Disclose
  the EGR denominator or add a `$/unit/mo` view alongside.
